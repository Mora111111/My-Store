4. DETAILED DESIGN
================================================================
4A. Checkout error modal (DRY reuse)
  Markup (in payment.php, mirroring #modal-success):
    <div class="container_modal popup" id="modal-error">
      <div class="popup_content">
        <i class="fa-solid fa-circle-exclamation popup_icon"
           style="font-size:70px;color:#ef4444;"></i>
        <p class="popup_p" id="checkout-error-text"
           style="font-size:18px;font-weight:bold;margin:20px 0;"></p>
      </div>
      <button class="popup_btn" id="btn-close-checkout-error"
        style="background:#ef4444;..."><?= lang('ok_btn') ?></button>
    </div>
  Why this shape:
  - .container_modal + .modal_active + .layer/.layer_active = the exact
    mechanism payment.js already drives; no new CSS/JS framework.
  - .popup variant is 300px centered — correct for short error text
    (vs full address form modal). Success modal proves the pattern.
  - lang() for title/button; dynamic server message injected via
    textContent (XSS-safe — never innerHTML for server strings).
  JS helper (in payment.js, defined once inside DOMContentLoaded):
    function showCheckoutError(msg) {
      var t = document.getElementById('checkout-error-text');
      if (t) t.textContent = msg;
      var m = document.getElementById('modal-error');
      if (m) m.classList.add('modal_active');
      if (layer) layer.classList.add('layer_active');
    }
    function hideCheckoutError() { remove both classes; }
  Replace each alert:
  - L236 empty-cart: showCheckoutError(lang string) then redirect.
    Keep redirect (UX decision unchanged) — or make modal button
    perform redirect. Recommend: show modal, and on close redirect.
  - L304: showCheckoutError(data.error || defaultLangString).
    Keep button-restore lines AFTER the call (modal is non-blocking
    unlike alert(), so restore must stay synchronous).
  - L310/L316: same, with generic server/connection lang strings.
  Close wiring: #btn-close-checkout-error click + .layer click (only
  when error modal is open, to avoid breaking address modals) call
  hideCheckoutError(). Also Escape key (nice-to-have).
  Critical subtlety: alert() blocks; modal does not. The existing
  button-restore code already runs synchronously after alert() today,
  so keeping it immediately after showCheckoutError() preserves
  behavior. Do NOT move restore into modal-close handler.
  Button label restore: L306/312/318 set textContent = "تأكيد الطلب"
  (hardcoded). Capture original innerHTML before disabling
  (const origBtnHtml = orderBtn.innerHTML) and restore that, or add
  lang('confirm_order_btn') (payment.php L129 already uses that key
  for the button — reuse it).

4B. Admin notifications (bell + dashboard section — recommended combo)
  Recommended: BOTH (a) header bell (global visibility) AND (b)
  dashboard section (actionable list). Bell alone has nowhere to act;
  section alone is invisible when admin is on other pages.
  (a) Bell in .header-actions (layout_start.php L202-209):
      - Button: <button id="stock-bell" class="view-store-btn"> with
        fa-bell icon + <span class="stock-badge">count</span>.
        Badge: absolute-positioned red pill; hidden when count = 0.
      - Dropdown: absolutely positioned panel under header listing
        top N out-of-stock products (image thumb 40px, title truncated,
        qty badge "0", link to /admin/products/edit?id=). Footer link
        "View all in Products". Toggle on bell click; close on
        outside click / Escape. Data server-rendered into the dropdown
        by AdminController (no AJAX needed Phase 1).
      - RTL: header uses flex + $pageDir for margins; position dropdown
        with inset-inline-end so it flips automatically. Reuse existing
        .view-store-btn base style for the bell to match header.
  (b) Dashboard section (dashboard.php, after .stats-grid-beautiful
      L172, before .welcome-card L174):
      - Card: red-accent left border (matching .stat-card::after idiom),
        title lang('out_of_stock_title') + count badge.
      - Table: image | product name | category | quantity (0, red) |
        action (restock/edit link). Max 5-10 rows + "view all" link.
      - Empty state: green check + lang('stock_ok_msg') when count = 0.
        Never render an empty table.
      - Optional 7th .b-card stat (c-stock class, red icon) showing the
        count — cheap and consistent with the 6 existing cards. Do this
        INSTEAD of overloading welcome-card.
  Backend:
      Product::countOutOfStock(): SELECT COUNT(*) FROM products
        WHERE quantity <= 0
      Product::getOutOfStockProducts(limit=8):
        SELECT id,title,image_url,category_class,quantity FROM products
        WHERE quantity <= 0 ORDER BY id DESC LIMIT ?
      AdminController::index(): $outOfStockCount, $outOfStockProducts.
      Threshold: v1 uses <= 0 only (true stockout, matches request).
      Add $lowStockThreshold=5 warning tier only as Phase 2 (amber).
  Live update (deferred): Phase 1 = server-render on page load.
      Phase 2 (if needed): GET /admin/api/stock-alerts returning
      {count, items[]} polled every 60s, updating badge + dropdown.
      Requires admin-session guard (AdminController::__construct
      already enforces admin role). CSRF not needed for GET read.

4D. Security / correctness notes
  - XSS: inject server error via textContent only. Product titles in
    admin dropdown via htmlspecialchars() (dashboard.php L175 already
    does this — follow it).
  - The HMAC/payment webhook work (PaymentController::callback) is
    unrelated — do not couple.
  - deductStock() atomic guard stays; admin restock links go through

    focus the close button on open, Escape to close.

6. RISKS & OPEN QUESTIONS
================================================================
- L236 empty-cart flow currently redirects immediately after alert().
  With non-blocking modal, decide: modal-then-redirect-on-close
  (recommended) vs keep instant redirect (modal unseen). Needs PO call.
- "تأكيد الطلب" restore string: confirm lang('confirm_order_btn')
  matches the initial button label in both languages before reusing.
- Payment page has TWO JS scopes (payment.js + inline script) both
  toggling .layer — new modal must use unique IDs (#modal-error) so
  generic document.querySelector('.container_modal') in payment.js L33
  (first match = add-address modal) is not disturbed; always select
  by ID for the error modal.
- Admin bell dropdown positioning inside .header (flex, no relative
  parent) needs position:relative on .header-actions or .header.
- Out-of-stock definition locked to quantity <= 0 per request; NULL
  quantities (legacy rows) — decide COALESCE(quantity,0) in queries.
- No new tables/migrations required. No new dependencies.
