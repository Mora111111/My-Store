STRICT PRICE-FLOW ARCHITECTURE AUDIT
--------------------------------------
Analysis of the exact numerical flow of prices from Frontend (home.php, products.php, app.js, payment.js) to Backend (CheckoutController.php).

1. BACKEND SECURITY STATUS: EXCELLENT ✅
The Backend is properly secured. It completely ignores `$_POST['total_price']` and `$_POST['products'][i]['price']`. Instead, it only extracts the product IDs and quantities from the frontend, then queries the database for the original prices, dynamically reconstructs the Strikethrough logic, subtracts the standard promo code, and strictly enforces the `shipping_cost`. This guarantees 100% price integrity against DOM manipulation.

However, there are critical DISCREPANCIES in the Frontend UI where the user will be shown the wrong math, causing confusion when they see a different amount ultimately charged/saved by the Backend.

2. FLAW 1: The Missing Shipping Cost in the UI
Issue: In `Js/app.js`, the `total_Price` saved to `localStorage` does NOT include the shipping cost (it only represents the Subtotal minus Promo Discount). But in `Js/payment.js` (Lines 46-48), the code blindly overrides all elements with the class `.order_total` (which includes the Final Total label) using this `total_Price` from `localStorage`.
Impact: The user reaches the checkout page and sees a final total that excludes shipping. The backend then adds shipping and saves a higher amount to the database, causing the UI and Backend to mismatch visually.
Fix for `Js/payment.js`:
Remove the aggressive overriding of `.order_total`. Allow `updateTotalPrice()` to calculate it dynamically based on the DOM.

Replace this in `Js/payment.js` (around line 46):
```javascript
    // Setup Total Price display
    const orderTotals = document.querySelectorAll(".order_total");
    const localTotal = window.localStorage.getItem("total_Price");
    orderTotals.forEach(el => el.textContent = localTotal ? localTotal : "0 جنيه");
```
With this:
```javascript
    // Allow updateTotalPrice() from app.js to control the rendering of final-total-price
    const orderTotals = document.querySelectorAll(".cart-total-price");
    const localTotal = window.localStorage.getItem("total_Price");
    orderTotals.forEach(el => el.textContent = localTotal ? localTotal : "0 ج.م");
```

3. FLAW 2: Coupon Object Key Mismatch (Silent UI Failure)
Issue: In `Js/app.js`, when calculating specific product discounts, it checks for `activeCoupon.target` and `activeCoupon.product_id` or `activeCoupon.type`. However, the new database schema uses `target_type`, `target_product_id`, and `discount_type`.
Impact: If the user applies a promo code, the Backend calculates it correctly and gives the discount, but the Frontend `app.js` silently fails to apply the math because `activeCoupon.target` is undefined. The UI will show a total of e.g. 200, while the backend correctly saves 150.
Fix for `Js/app.js`:
Update the property accessors to match the exact database columns returned by the API.

Replace lines 246-274 in `Js/app.js` with this:
```javascript
        const tType = activeCoupon.target_type || activeCoupon.target;
        const targetId = activeCoupon.target_product_id || activeCoupon.product_id;
        const dType = activeCoupon.discount_type || activeCoupon.type;
        const dValue = parseFloat(activeCoupon.discount_value || activeCoupon.value || 0);

        if (activeCoupon && tType === 'specific_product' && targetId == itemId) {
            specificProductSubtotal += itemTotal;
        }
    });

    let discountTotal = 0;
    if (activeCoupon) {
        const tType = activeCoupon.target_type || activeCoupon.target;
        const dType = activeCoupon.discount_type || activeCoupon.type;
```

4. FLAW 3: CheckoutController Logic
I audited the `CheckoutController.php` against `home.php`. The calculation for Strikethrough pricing and Promos is a 1:1 identical match. No flaws detected here. The backend safely executes exactly what the frontend advertises.

FINAL RECOMMENDATION:
The data synchronization and security are generally brilliant. You just need to fix the UI rendering (Flaw 1) and the Coupon JS object keys (Flaw 2) so the user's browser calculates the exact same math as the impenetrable Backend.
